Understanding LoRA

Updated: 6 Feb, 2026
| Edit page

What is LoRA?

LoRA is a Parameter-Efficient Fine-Tuning (PEFT) Method that uses low-rank approximation (LoRA) to reduce the computational cost of fine-tuning LLMs. By applying low-rank decomposition, LoRA fine-tunes LLMs by updating a small set of parameters, which are more memory-efficient and computationally efficient than updating all parameters (full-fine-tuning).

Introduction to LoRA

Key Assumptions

LoRA assumes that the intrinsic dimension of the LLM for each sub-task is small, despite the fact that the number of total parameters is large. Based on this assumption, LoRA uses a low-rank approximation to reduce the computational cost of fine-tuning LLMs.

LoRA Algorithm

Let WWW be the parameter matrix of the LLM. For the full-fine-tuning, the update rule is:

Wt+1=Wt+ΔW,W^{t+1} = W^t + \Delta W,Wt+1=Wt+ΔW,

when W∈Rd×dW\in \mathbb{R}^{d\times d}W∈Rd×d is a large matrix, it requires both computation and memory to do the update.

As for LoRA, it uses A∈Rd×r,B∈Rr×dA\in \mathbb{R}^{d\times r}, B\in \mathbb{R}^{r\times d}A∈Rd×r,B∈Rr×d to replace the ΔW\Delta WΔW. The update rule is:

Wt+1=Wt+AB,W^{t+1} = W^t + AB,Wt+1=Wt+AB,

where AAA and BBB are the low-rank approximations of ΔW\Delta WΔW, r≪max⁡{d,k}r\ll \max\{d,k\}r≪max{d,k}. In practice, AAA is initialized with Gaussian distribution, and BBB is initialized with zeros.

LoRA Analysis

Naively implementing the LoRA will not save the day.

Naive Implementation

For the naive implementation, the update rule is:

Y=XW=X(W0+AB),Y = XW = X(W_0 + AB),Y=XW=X(W0​+AB),

where X∈Rb×nX\in \mathbb{R}^{b \times n}X∈Rb×n is the input matrix.

We can get the gradient of A,BA,BA,B by back-propagation.

∂L∂A=∂L∂WBT,∂L∂B=AT∂L∂W.\frac{\partial L}{\partial A} = \frac{\partial L}{\partial W}B^T, \frac{\partial L}{\partial B} = A^T\frac{\partial L}{\partial W}.∂A∂L​=∂W∂L​BT,∂B∂L​=AT∂W∂L​.

Obviously, it requires the entire WWW to compute the gradient, which is not efficient.

Efficient Implementation

Set the intermediate result Z=XA∈Rb×rZ=XA \in \mathbb{R}^{b\times r}Z=XA∈Rb×r, we have:

Y=XW0+XAB=XW0+ZB.Y = XW_0 + XAB = XW_0 + ZB.Y=XW0​+XAB=XW0​+ZB.

Now the gradient is:

∂L∂A=XT∂L∂Z,∂L∂B=ZT∂L∂Y.\frac{\partial L}{\partial A} = X^T\frac{\partial L}{\partial Z}, \frac{\partial L}{\partial B} = Z^T\frac{\partial L}{\partial Y}.∂A∂L​=XT∂Z∂L​,∂B∂L​=ZT∂Y∂L​.

Now it will save the memory and computation cost.

Memory Analysis

For the backbone model, it saves the memory cost, especially the first-order and second-order gradients for optimizers like Adam. Additionally, the backbone model can be quantized into INT8 or even INT4 as it does not require updates.

LoRA also saves the communication cost across GPUs.

Initialization Choice

One of the frequently asked question is how to initialize A,BA,BA,B.

Let us think about this step by step.

  • First, can’t initialize both matrices with 0. Because this will lead to 0 gradients.
  • Second, can’t initialize both A,BA,BA,B with Gaussian distribution. Because this may lead to high ΔW\Delta WΔW, resulting deviation from the pre-trained model at the very first step.
  • Third, with AAA initialized with Gaussian distribution, the BBB can be initialized with zeros. BBB can still get gradients while the initial ΔW\Delta WΔW is 0 at the beginning.
  • Finally, there is no rules that BBB cant be initialized with Gaussian distribution as AAA to be zeros. Some paper claims that AAA to be Gaussian distribution is better but there is no guarantee.
